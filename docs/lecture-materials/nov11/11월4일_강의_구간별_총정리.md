## 3부 (40:00–60:00): React Context API 개념

- 슬라이드 제목 `Context란 무엇인가?`.
- Context는 부모에서 자식으로 매번 props를 중간 단계마다 내려보내는 **Props Drilling**을 줄이는 방법.
- 공유하기 쉬운 값 예시: 테마, 사용자 정보, 언어 설정.
- `createContext`로 Context를 정의하고 Provider가 범위 내에 값을 제공, 소비자 컴포넌트는 `useContext`로 가져옴.
- 무조건 모든 state에 Context를 쓰라는 뜻은 아님. 값의 갱신 주기, 소비자 재렌더링 등 성능을 고려.
- 화면에는 Next.js의 Server Component에서 `useContext`를 직접 사용할 수 없다는 제한이 소개됨.

## 4부 (60:00–80:00): createContext / Provider / useContext 기초

슬라이드 예시 코드:

```tsx
const MyContext = React.createContext('Hello from Context');
function MyComponent() {
  const value = useContext(MyContext);
  return <div>{value}</div>;
}
function App() {
  return (
    <MyContext.Provider value="Hello from Context">
      <MyComponent />
    </MyContext.Provider>
  );
}
```

- `useContext(MyContext)`는 현재 컴포넌트 위쪽 트리에서 **가장 가까운 해당 Provider의 value**를 받음.
- Next.js에서는 Context provider를 `'use client'` 컴포넌트로 만들고 서버 레이아웃에서 children으로 감싸는 패턴을 소개.
- 76분대 `theme-provider.tsx` 예제에서 `ThemeContext.Provider`로 `children`을 감싸는 화면 확인.

## 5부 (80:00–100:00): ThemeProvider, ThemeStatus 구현

영상에서 확인한 파일명:
- `src/components/ThemeProvider.tsx`
- `src/components/ThemeStatus.tsx`

테마 Context의 데이터 구조:

```tsx
type Theme = 'light' | 'dark';
type ThemeContextValue = {
  theme: Theme;
  toggleTheme: () => void;
};
```

- `createContext<...>({theme:'light', toggleTheme:()=>{}})`로 기본값과 타입 정의.
- `useState<'light' | 'dark'>('light')`로 현재 테마를 저장.
- `toggleTheme`는 `setTheme(t => t === 'dark' ? 'light' : 'dark')`로 상태 전환.
- `useEffect`에서 `document.documentElement.dataset.theme = theme`를 설정함.
- `ThemeStatus`는 `useContext(ThemeContext)`로 `theme`, `toggleTheme`를 받고, 버튼 클릭으로 실행.
- 개발 중 import 경로가 잘못되어 오류 표시가 나온 장면이 확인됨. 배포 가능한 프로젝트에서는 맞는 상대 경로로 고침.

## 제일 중요한 데이터 흐름

```
RootLayout (Server Component)
└─ ThemeProvider (Client Component, state 보유)
   ├─ ThemeStatus (Client, useContext/버튼 클릭)
   └─ {children}: HomePage, CounterPage, InterleavedPage 등
        └─ InterleavedPage (Server)
           └─ ClientLayout (Client, children 슬롯)
              └─ ServerContent (Server, 서버에서 fetch)
```

테마 버튼 클릭 시:
`ThemeStatus.onClick` → `toggleTheme()` → `setTheme(...)` → Provider value 갱신 → 소비자 UI 업데이트 → `useEffect` 실행 → `<html data-theme="dark">` → CSS 색상 변경.

## 반드시 구분할 개념

| 개념 | 역할 |
| --- | --- |
| Server Component | 서버에서 데이터와 UI를 준비; `async` 데이터 조회 가능 |
| Client Component | 브라우저 상호작용, `useState`, `useContext`, 이벤트 핸들러 사용 |
| Interleaving | 서버 부모가 Server Component를 Client Component의 `children`으로 전달 |
| Props Drilling | 중간 컴포넌트가 사용하지 않는 props까지 여러 단계로 전달하는 문제 |
| Context | 특정 하위 트리의 소비자들이 공유 값을 읽도록 제공 |
| Provider | Context에 실제 값을 제공하고 컴포넌트들을 감싸는 역할 |
| useState | 로컬 상태를 만들고 변경할 수 있게 함 |
| useContext | 현재 컴포넌트 위쪽의 Provider에서 가장 가까운 값을 읽음 |
| useEffect | 렌더링 이후 DOM 등 외부 시스템과 동기화하는 부수 효과 처리 |
| data-theme | CSS에서 테마별 스타일을 적용할 수 있도록 HTML 요소에 둔 속성 |

## 강의 복습 문제
1. 서버 컴포넌트를 클라이언트 컴포넌트의 `children`으로 전달할 수 있는 이유는 무엇인가?
2. `ThemeProvider`에 `'use client'`가 필요한 이유는 무엇인가?
3. `createContext`의 기본값은 언제 사용하는가?
4. `ThemeStatus`에서 `useContext`가 읽는 것은 무엇인가?
5. `useEffect` 없이 `data-theme`를 적용할 수 있는 방법은 무엇이며, 이 강의에서는 왜 `useEffect`를 활용했는가?
6. Context가 Props Drilling을 줄이는 방식과, 모든 데이터를 Context에 담으면 안 되는 이유는 무엇인가?

## 답의 핵심
1. 서버 부모가 서버 결과를 React 요소로 준비하여 클라이언트 컴포넌트의 props 슬롯으로 전달하는 패턴이기 때문.
2. `useState`, `useEffect`로 상태와 DOM 부수효과를 처리하기 때문.
3. 컴포넌트 위쪽에 해당 Provider가 없을 때 fallback으로 사용.
4. 트리에서 가장 가까운 `ThemeContext.Provider`의 value 객체.
5. CSS `prefers-color-scheme`이나 다른 DOM 조작 방식도 가능하지만, 수업에서는 React 상태를 `html` 속성에 동기화하는 흐름을 설명.
6. 중간 props 전달을 줄이지만 Provider의 값 변경은 해당 Context를 읽는 소비자들의 재렌더링을 일으킬 수 있으므로 범위를 적절히 정해야 함.
