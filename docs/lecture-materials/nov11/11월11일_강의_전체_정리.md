## 3. Context API 복습

### 3-1. Context가 필요한 이유

부모 컴포넌트의 값을 여러 단계 아래의 자식 컴포넌트에서 사용하려면 일반적으로 Props를 전달한다. 여러 중간 컴포넌트를 거쳐 계속 전달해야 하는 상황을 Props Drilling이라고 한다.

Context는 Provider 아래에 있는 하위 컴포넌트가 공통 값을 읽을 수 있도록 한다. 영상에서는 테마, 언어 설정, 로그인 정보 등을 예로 들었다.

### 3-2. `createContext`

`createContext`는 React 컴포넌트 트리에서 공유할 Context 객체를 만든다.

영상에서 설명한 형태:

```tsx
export const ThemeContext = createContext<{
  theme: 'light' | 'dark';
  toggleTheme: () => void;
}>({
  theme: 'light',
  toggleTheme: () => {},
});
```

- `theme: 'light' | 'dark'`: theme은 두 문자열 중 하나만 가질 수 있다.
- `toggleTheme: () => void`: 인자를 받지 않고 반환값이 없는 함수다.
- `createContext`에 전달한 객체는 Provider가 없을 때 사용되는 기본값(fallback)이다.
- 기본값의 `toggleTheme`는 동작하지 않는 빈 함수이며, 실제 동작은 Provider에서 전달한다.

### 3-3. 유니온 타입(Union Type)

`'light' | 'dark'`처럼 `|`로 여러 타입을 연결하면 그중 하나의 값만 허용한다.

```tsx
type Theme = 'light' | 'dark';

const [theme, setTheme] = useState<Theme>('light');
```

이렇게 하면 `theme`에 `light` 또는 `dark`만 저장할 수 있어 자동완성과 타입 안정성에 도움이 된다.

### 3-4. Provider

`ThemeContext.Provider`는 하위 컴포넌트에 Context 값을 제공한다.

```tsx
<ThemeContext.Provider value={{ theme, toggleTheme }}>
  {children}
</ThemeContext.Provider>
```

- `value`에 공유할 상태와 함수를 넣는다.
- `{children}`은 Provider로 감싸는 하위 컴포넌트들이다.
- Provider 아래의 하위 컴포넌트는 `useContext(ThemeContext)`로 값을 읽을 수 있다.

### 3-5. `useContext`

```tsx
const { theme, toggleTheme } = useContext(ThemeContext);
```

현재 컴포넌트보다 위쪽에 있는 가장 가까운 `ThemeContext.Provider`의 `value`를 읽는다.

### 3-6. `useEffect`와 브라우저 전용 객체

영상 코드:

```tsx
useEffect(() => {
  if (typeof window !== 'undefined') {
    document.documentElement.dataset.theme = theme;
  }
}, [theme]);
```

- `useEffect`: 렌더링 후 외부 시스템과 동기화하는 Effect를 실행한다.
- `window`: 브라우저 환경에서 제공되는 전역 객체다.
- `typeof window !== 'undefined'`: 브라우저 환경인지 확인한다.
- `document.documentElement`: HTML 문서의 `<html>` 요소를 가리킨다.
- `dataset.theme = theme`: HTML 요소에 `data-theme` 속성을 설정한다.
- `[theme]`: theme 값이 변경될 때 Effect를 다시 실행한다.

`useEffect`는 서버 렌더링 중 실행되지 않지만, 영상에서는 브라우저 환경을 확인하는 조건문도 함께 사용했다.

### 3-7. CSS 속성 선택자

영상에서 설명한 스타일 예:

```css
html[data-theme='light'] {
  background-color: white;
  color: black;
}

html[data-theme='dark'] {
  background-color: black;
  color: white;
}
```

`[data-theme='dark']`는 `data-theme` 속성이 `dark`인 HTML 요소를 선택한다. 클래스나 ID 대신 속성값으로 스타일을 분기할 수 있다.

## 4. ThemeProvider 전체 코드

영상 화면에서 확인한 코드 구조를 읽기 쉽게 정리한 것이다.

```tsx
'use client';

import { createContext, useEffect, useState } from 'react';

export const ThemeContext = createContext<{
  theme: 'light' | 'dark';
  toggleTheme: () => void;
}>({
  theme: 'light',
  toggleTheme: () => {},
});

export default function ThemeProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light');

  useEffect(() => {
    if (typeof window !== 'undefined') {
      document.documentElement.dataset.theme = theme;
    }
  }, [theme]);

  const toggleTheme = () => {
    setTheme((t) => (t === 'dark' ? 'light' : 'dark'));
  };

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}
```

### 코드 해설

1. `'use client'`: `useState`, `useEffect`를 사용하는 클라이언트 컴포넌트 경계다.
2. `createContext`: 테마 상태와 토글 함수를 공유할 Context 객체를 만든다.
3. `useState`: 초기 테마를 `light`로 설정한다.
4. `useEffect`: 테마가 바뀌면 HTML의 `data-theme` 값을 갱신한다.
5. `toggleTheme`: `light`와 `dark`를 서로 바꾼다.
6. `Provider`: `{ theme, toggleTheme }`를 하위 트리에 제공한다.

## 5. ThemeStatus 코드

영상에서 확인한 코드:

```tsx
'use client';

import { useContext } from 'react';
import { ThemeContext } from './theme-provider';

export default function ThemeStatus() {
  const { theme, toggleTheme } = useContext(ThemeContext);

  return (
    <div style={{ display: 'inline-block', marginLeft: 12 }}>
      <button onClick={toggleTheme} aria-label="toggle theme">
        Theme: {theme === 'dark' ? '🌙 Dark' : '☀️ Light'}
      </button>
    </div>
  );
}
```

- `useContext(ThemeContext)`로 Provider가 제공한 값을 읽는다.
- 버튼 클릭 시 `toggleTheme`를 실행한다.
- 삼항 연산자로 현재 테마에 맞는 텍스트와 아이콘을 표시한다.
- `aria-label`은 보조 기술이 버튼의 역할을 이해할 수 있도록 접근 가능한 이름을 제공한다.

## 6. RootLayout에 Provider 배치

영상에서는 `RootLayout`에 `ThemeProvider`와 `ThemeStatus`를 추가했다.

개념 구조:

```tsx
import ThemeProvider from '@/components/ThemeProvider';
import ThemeStatus from '@/components/ThemeStatus';

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <ThemeProvider>
          <header>
            <ThemeStatus />
          </header>
          <main>{children}</main>
          <footer>Root Layout Footer</footer>
        </ThemeProvider>
      </body>
    </html>
  );
}
```

Provider로 감싼 하위 트리의 컴포넌트들이 Context에 접근할 수 있다. `children`은 RootLayout으로 전달되는 페이지/하위 컴포넌트다.

영상 슬라이드에서는 `<html>`과 `<body>`도 Provider로 감싸는 구성을 설명했다. 다만 이 프로젝트에서는 `html`과 `body`를 Next.js RootLayout의 최상위 구조로 유지하고, 그 안에서 페이지 트리를 Provider로 감싸는 형태를 사용한다.

## 7. Context Provider 실행 순서

버튼을 클릭했을 때의 흐름:

1. 사용자가 `ThemeStatus`의 버튼을 클릭한다.
2. `toggleTheme()`가 호출된다.
3. Provider 내부의 `setTheme`이 실행되어 theme 상태가 바뀐다.
4. Provider와 그 하위에서 Context를 사용하는 컴포넌트가 최신 값을 받아 다시 렌더링된다.
5. `useEffect`가 실행되어 `document.documentElement.dataset.theme`를 갱신한다.
6. CSS의 `data-theme` 선택자가 적용되어 실제 화면 스타일이 바뀐다.

## 8. 외부(서드 파티) 컴포넌트

### 8-1. 외부 컴포넌트란?

외부 컴포넌트는 애플리케이션에서 직접 구현하지 않고 npm 등 패키지로 설치해 사용하는 UI 컴포넌트다. 영상에서는 `acme-carousel` 패키지의 `Carousel`을 예로 들었다.

Carousel은 웹사이트나 앱에서 여러 이미지, 비디오, 텍스트를 순서대로 보여주는 UI 요소다.

### 8-2. 왜 Client Component 안에서 사용해야 하는가?

영상 설명에서는 외부 `Carousel` 컴포넌트가 `useState` 같은 클라이언트 전용 기능을 사용하지만 패키지 내부에 `'use client'` 지시문이 없을 수 있다고 설명했다.

이 컴포넌트를 Server Component에서 직접 사용하면 클라이언트 전용 기능을 사용하는 컴포넌트 경계가 명확하지 않아 오류가 발생할 수 있다.

해결 방법으로 외부 컴포넌트를 Client Component 경계 안에서 사용한다.

영상의 Gallery 예시:

```tsx
'use client';

import { useState } from 'react';
import { Carousel } from 'acme-carousel';

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/* Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  );
}
```

### 8-3. Server Component에서 쓰려면 Client Wrapper

영상 슬라이드의 래퍼 패턴:

```tsx
// carousel.tsx
'use client';

import { Carousel } from 'acme-carousel';

export default Carousel;
```

서버 페이지:

```tsx
import Carousel from './carousel';

export default function Page() {
  return (
    <div>
      <p>View pictures</p>
      <Carousel />
    </div>
  );
}
```

실제 패키지의 TypeScript 타입에서 `items`가 필수라고 확인된 이후에는 `<Carousel />`만 사용하면 안 되고 `items`를 전달해야 한다.

### 8-4. 설치 오류와 필수 Props 오류

영상에서 확인한 오류:

```text
Cannot find module 'acme-carousel' or its corresponding type declarations.
```

패키지가 설치되지 않았을 때 발생한 모듈 오류다. 강의에서는 패키지 설치로 해결한다.

설치 이후에는 다음 타입 오류가 발생했다.

```text
Property 'items' is missing in type '{}' but required in type 'CarouselProps'.
```

이는 `CarouselProps` 타입에서 `items`가 필수로 정의되어 있는데, `<Carousel />`에 props를 전달하지 않았기 때문이다.

### 8-5. items 배열 작성

영상에 나온 더미 이미지 목록:

```tsx
const items = [
  {
    id: '1',
    src: 'https://picsum.photos/id/1015/800/600',
    alt: 'Landscape 1',
  },
  {
    id: '2',
    src: 'https://picsum.photos/id/1016/800/600',
    alt: 'Landscape 2',
  },
  {
    id: '3',
    src: 'https://picsum.photos/id/1018/800/600',
    alt: 'Landscape 3',
  },
];

return (
  <Carousel items={items} />
);
```

- `id`: 각 항목을 구분하기 위한 값
- `src`: 이미지 주소
- `alt`: 이미지 대체 텍스트
- `items`: Carousel에 표시할 항목 배열

### 8-6. CSS가 적용되지 않는 문제

영상에서는 오류를 수정한 뒤 캐러셀 동작은 하지만 이미지가 첫 페이지에 모두 출력되는 것처럼 보이는 문제가 나왔다.

강의 슬라이드에서 설명한 원인은 `acme-carousel`의 스타일이 적용되지 않은 것이었다.

패키지 CSS 경로는 다음과 같이 안내되었다.

```css
@import 'acme-carousel/dist/styles.css';
```

하지만 해당 패키지에서는 이 방식으로 문제가 발생하여, 강의에서는 스타일 파일을 `components/` 쪽에 복사하고 `gallery.tsx`에서 로컬 CSS를 import하는 방법을 제시했다.

```tsx
import './styles.css';
```

이 프로젝트의 실행 가능한 데모에는 패키지의 실제 CSS 파일을 포함하지 않았다. 대신 직접 작성한 `src/components/gallery/styles.css`를 사용한다. 실제 `acme-carousel` 패키지의 스타일 파일과 동일하다고 볼 수는 없다.

### 8-7. default export와 named export

영상에서는 `Slide`를 named export처럼 가져오면 오류가 발생한다고 설명했다.

잘못된 예:

```tsx
import { Carousel, Slide } from 'acme-carousel';
```

슬라이드에서 안내한 방식:

```tsx
import { Carousel } from 'acme-carousel';
import Slide from 'acme-carousel';
```

- named export: `import { Carousel } from '...'`
- default export: `import Slide from '...'`

단, 이 예제의 `Slide`를 실제 화면에서 어떻게 조합하는지는 영상에서 완성된 실행 코드까지 확인되지 않았으므로, 프로젝트의 실행 경로에는 넣지 않았다.

## 9. 영상에서 확인한 Carousel API 항목

API Reference 화면에서 읽을 수 있었던 항목:

| Prop | 화면에 보인 타입/설명 |
|---|---|
| `items` | `CarouselItem[]`, 표시할 항목 배열, 필수 |
| `currentIndex` | `number`, 현재 슬라이드 인덱스 제어, 기본값 0 |
| `onSlideChange` | `(index: number) => void`, 슬라이드 변경 콜백 |
| `autoplay` | `AutoplayConfig`, 자동 재생 설정 |
| `navigation` | `NavigationConfig`, 내비게이션 설정 |
| `pagination` | `PaginationConfig`, 페이지네이션 설정 |
| `touch` | `TouchConfig`, 터치/스와이프 설정 |
| `responsive` | `ResponsiveConfig`, 반응형 설정 |
| `className` | `string`, 사용자 CSS 클래스 |

API 화면 일부만 확인 가능했기 때문에 이 표에 없는 옵션이나 상세 기본값은 추가로 추측하지 않았다.

## 10. 이번 프로젝트에서 실제로 구현한 부분과 재구성한 부분

### 강의 화면에 근거한 부분
- Context API 기반 ThemeProvider
- ThemeStatus의 useContext 사용
- useEffect로 HTML의 `data-theme` 설정
- RootLayout에 Provider 배치
- Client Component 안에서 외부 Carousel 사용
- `items` 배열을 Carousel에 전달하는 방식
- `acme-carousel` 관련 import 및 CSS 오류의 원인

### 실행을 위해 재구성한 부분
- `acme-carousel`의 내부 구현을 복제하지 않고 로컬 `LocalCarousel` 컴포넌트를 작성
- 이전/다음 버튼, 페이지 표시, 자동 재생 기능 추가
- Gallery 페이지를 `/gallery`로 구성
- 외부 이미지 주소를 사용한 실습 데이터
- README와 실행 안내

따라서 ZIP은 강의 개념을 따라 실습할 수 있는 실행 가능한 프로젝트이며, npm의 `acme-carousel` 원본 패키지를 그대로 복제한 것은 아니다.
